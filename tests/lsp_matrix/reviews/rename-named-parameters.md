# Source function named-parameter ownership

B04.05 advances the positive/negative S5 service/protocol partitions for references,
highlights, prepareRename and rename. These broad cells remain unreviewed; this
slice covers source function parameters, not all method/schema/variant/callable
value or argument syntax ownership.

The independent three-file fixture enumerates 16 query positions in three local
binding groups and three empty outcomes. It distinguishes a callee's parameter
from a same-spelled caller variable and another function's parameter. Owned labels
occur in aliased imports, qualified calls, closures, default expressions, an
initially unopened consumer, and a call with a missing value. Unknown parameter
labels, unknown callees and literal contents have no invented rename target.

Both drivers run LF/CRLF with Unicode prefixes; protocol uses an encoded Unicode
workspace path. Every query repeats exact reference sets with/without declarations,
highlight ranges/kinds, prepare ranges/placeholders, and complete rename edits.
The service checks symbol identities; named queries also verify exact definition
targets. All three groups are actually renamed, entire files are compared with
independent marked-source expectations, and all queries run again before and after
restoration. Protocol sends didChange and verifies both UTF-16 edit forms with
client versions, including the subsequently closed consumer's null version.

The missing-value case explicitly asserts that its recovered CST named argument
has no value expression. An existing parameter name and an unknown label belonging
to the same source function reject rename. A same-spelled unknown label on a
different function does not cause false rejection or become an owned reference.

Named-argument sites now reuse the resolved source signature used by navigation,
then map the parameter span to its canonical HIR local ID. Reference, highlight
and rename share this ownership. Rename plans use the owning declaration's source
and gather edits across documents, so a query at a caller's label cannot use the
caller's text to project a parameter declaration in another file. Candidate labels
are filtered by queried range or relevant names before resolving callees.

The source function scope is explicit: method, schema and tuple-variant parameter
ownership is not certified by this slice. Field-target rename remains B04.06 work,
followed by the remaining semantic/lifecycle and UX05/UX06 gates. Original B00-B03
snapshots stay fixed; fresh regression evidence belongs to the current registered
profile. macOS needs its own fresh evidence when used; B16 remains deferred.
