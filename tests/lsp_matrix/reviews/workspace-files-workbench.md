# Installed Explorer dependency changes

B09.3 covers exactly the six UX17 Explorer create/rename/delete Command and Input
obligations. Roots/settings, static schema and UX21 trust remain separate pending
work. `input-workspace-files.json` authors distinct package modules, Chinese/emoji
markers, unchanged disk callers and a literal unsaved prefix. Independent tests
pin LF/CRLF UTF-16 call and definition coordinates before any editor observation.
Go to Line/Column uses a separately authored visible column for the wide Chinese
character; it does not change the expected LSP position.

Each route types the prefix through the real editor. A standard command query
must return the complete current definition list; actual F12 must produce one
completed installed-client request with the exact caller position and complete
Location-or-null result. The real editor must land at the expected current file,
range start and source text, or preserve the exact dirty caller for a missing
definition. Every source check includes language, caret, dirty state and disk.
Complete diagnostic publications retain code, severity, range, source, labels,
candidates and repair hints, with URIs normalized to owned workspace files.

Creation selects the package's scripts folder, uses Explorer New File, types and
saves the dependency, then requires the missing-module diagnostic to clear and
the exact new definition to appear. Rename uses the selected Explorer file and
F2. The old import must fail with a null native target; a real unsaved import
edit restores the renamed definition. The old disk path must be absent and the
new path must retain the exact dependency bytes. Delete uses the Explorer context
menu and its confirmation. The dependency must disappear, both queries must lose
the target and the exact missing-module diagnostic must appear. Recreating it
through Explorer must restore navigation and clear the diagnostic without saving
the caller. Readiness only observes; accepted actions execute once per route.

Investigations retain initial visible-column, asynchronous Quick Open selection,
menu readiness and application-scope failures. A separate private-window DOM
investigation confirms the real confirmation. The pinned Monaco source installs
mouse-up handlers 100 ms after rendering to suppress the context-opening gesture;
a menu becoming visible does not yet make a click actionable. The driver observes
150 ms after first visibility before its single Delete action-label click, and
retains the timestamps. Quick Open clicks its unique
exact native file result. Rename completion waits for the authored disk membership
and the end of Explorer's inline edit before subsequent input. No source, range,
diagnostic or recovery expectation is relaxed. These are driver corrections;
this child changes no production Rust behavior.

The first full regression also exposes a pre-existing Quick Fix readiness race:
the manual request returns the expected fixes, but an overlapping automatic
refresh hides its widget. Setup now observes the existing workspace-mutation
quiet window before the single shortcut/lightbulb action. Prior Quick Fix source,
diagnostic, menu, action and recovery contracts remain unchanged; its full failed
attempt is retained and all proof is recollected after this driver correction.
The following full run passes all 42 prior routes and Explorer creation/rename,
then exposes duplicate `scripts` matches during deletion recovery: the scrolled
tree renders a sticky ancestor copy with the same label and DOM id. Folder setup
now uses actual Home input and matches the unique real tree row, excluding that
visual copy; it does not choose an arbitrary first match or relax ownership.

Both registered profiles explicitly pin `window.dialogStyle: "custom"` and
`explorer.confirmDelete: true`. Confirmation remains a real workbench dialog,
including the final pointer click.
The confirmation's complete accessible name, button, screenshot and ARIA snapshot
must identify the authored dependency before the pointer click. The configuration declares
dialog style at APPLICATION scope; the driver writes it into this run's private
user-data/User/settings.json, rather than the workspace or the developer's user
settings. Other settings remain workspace scoped. The observer verifies the
entire effective profile. On macOS Explorer context input reuses the existing
owned-process native menu helper; Windows uses the Electron menu. This reviewed
profile adjustment invalidates prior live bundles, so acceptance recollects the
whole installed suite and all existing native proofs against one frozen source.

Each route has a 60-second deadline within the run's 180-second bound. Hashed
screenshots, ARIA snapshots, raw client/server logs, command results, action and
assertion receipts, VSIX and installed binary retain the source/profile identity.
Windows evidence does not certify the unexecuted macOS paths; that machine must
recollect its own current proof. Original accepted batches and previous children
remain historical snapshots, and B16 stays deferred.
