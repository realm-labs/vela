# Workspace roots and settings workbench review

B09.5's UX17 roots/settings contract owns command and real-input obligations.
The independent marked fixture contains two anonymous roots, a Unicode dirty
definition, two dirty callers and an unopened target with a distinct range.
Complete definition responses, actual caret/selection, unchanged disk bytes,
current folder/settings state and full diagnostic payloads have authored oracles.
Go-to-Line's authored display columns account for the Han glyph's width, while
queries and response ranges retain independent UTF-16 positions. LF/CRLF
fixture tests pin both coordinate systems and the shifted unsaved target.

Native Add Folder and Save Workspace As establish an owned multi-root workspace
after the previous routes. Full-source selection, Backspace, empty-editor checks,
exact inserted JSON/caret and exact saved bytes guard settings replacements.
The five phases cover both roots, a settings-only right-root selection, restored
settings, actual left-folder removal and physical readdition. A left dirty
caller outside current source roots becomes scratch: neither import may keep a
binding. The independent right caller must retain its current target. Restoring
roots clears both import diagnostics and restores the unsaved left definition.

First-folder changes can restart the installed extension host. The driver retains
the preceding and current session logs, checks the launched server's owned cwd,
and observes initial publications from the new client instead of applying an old
log offset. Changes within one session require fresh post-mutation publications.
Complete workspace JSON still preserves all pinned preferences after native
folder removal/readdition. F12's editor caret collapses at the definition start,
as in the existing navigation contracts; full wire identifier ranges remain exact.

Each of the fifteen locations is checked through the definition command and a
separate physical F12, including full null responses, visible no-target messages
and no caret movement for scratch imports. Observers only read state and query;
accepted workspace changes use keyboard/pointer input. Generated workspace
identity is setup metadata; semantic expectations come from this fixture.
Per-platform JSON differs only in the pinned font. Both exact byte/caret contracts
remain required, while the infrastructure comparison normalizes that physical
font difference. The Windows roots checkpoint passed all five phases and fifteen
command/native pairs in a complete 47-proof run plus the strict prior-batch gate.
Subsequent source changes require a fresh complete run, including the appended
invalid-input route, before B09.5 acceptance; macOS needs its own captures.
The driver waits for the new owned host immediately after first-folder changes,
before subsequent UI actions or observation requests can use a closing socket.

Both registered profiles enable the editor's real file/folder picker through
`files.simpleDialog.enable`. Primary code in the pinned desktop workbench gates
its simplified file dialog on this setting, independently of confirmation
`window.dialogStyle`. Two initial failed driver attempts retain snapshots: the
first typed before dialog readiness; the second waited for a workbench dialog
while the file-picker setting still selected an external system window. These
are driver failures and do not establish a language-service defect or acceptance.
