# B06 installed semantic-token provider review

Three editor smoke obligations use the installed VSIX and its real bundled
language client. A manually authored fixture specifies all 43 original tokens
and both 45-token edited streams. Expected types/modifiers reflect the client's
negotiated standard fallback contract; source/unresolved custom modifiers are
not advertised by this client. No expected classification comes from a provider.

LF and CRLF runs preserve Chinese/non-BMP comments, then insert two Unicode
lines and replace a source receiver hint with Any while renaming its local.
The typed field changes property to lexical variable; unrelated dynamic and
unresolved qualified names remain lexical. Every token's text, kind, complete
modifiers, length and UTF-16 coordinates must match the independent markers.
Closing unsaved edits restores physical disk bytes and the original full stream.

Public VS Code full commands verify complete and repeated data. Range commands
use the same negotiated legend and verify every token range, each occupied line
and an empty document-start range twice. Bounds, tuple shape, ordering,
non-overlap, surrogate boundaries and unknown legend bits are checked explicitly.

The delta proof does not manufacture a client or send a test-owned LSP request.
It waits for the workbench renderer's initial stream before running public full
queries, then observes the installed client's own verbose log. A retained renderer
cache may supply an empty delta from an observed full instead of a new full.
Both edits must
produce a new, complete, matched full/delta response with nonempty edits and an
observed predecessor whose complete data matches the preceding independent
state. Applying actual word edits must equal the next independent stream and a
fresh public full. Request/response identity, partial flushes and malformed data
have sensitivity checks. Retained observations include wire requests/responses,
previous words, applied words and the full client log.

Editor input fingerprints include the shared matrix scripts, so changes to the
independent oracle, decoder or passive trace parser invalidate old provider
evidence even when the installed extension and server bytes remain identical.
An explicit freshness sensitivity test covers that boundary.

This child certifies provider smoke only. The six UX09 native input/render cells
remain open; provider results cannot substitute for workbench interaction.
B00-B05 acceptance is preserved, profiles need independent fresh proof, and B16
remains deferred.
