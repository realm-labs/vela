# Workspace configuration and folder invalidation

B09.2 owns nineteen protocol obligations: configuration-change S0/S9/S11
positive and negative plus capabilities; workspace-folders S0/S8/S11 positive
and negative, stale work, cancellation and capabilities; configuration-request
S0/S11 negative plus capabilities. Existing positive conditional exemptions
remain unchanged because the server does not issue workspace/configuration
requests. Installed UX17 workspace and UX21 trust obligations remain open.

The independently authored workspace-configuration fixture supplies two source
roots, Unicode declaration/call/import markers, a shifted unsaved definition,
manifest-owned roots and two incompatible static host schemas. A Node golden
pins literal UTF-16 coordinates under LF/CRLF, complete import reference ranges
and schema field names/types. No provider response supplies expected facts.

Six editor setting forms exercise nested, wrapped and flat settings, precedence,
empty-root fallback and restoration. Complete diagnostic publication URI sets
and full diagnostic data distinguish active modules, excluded modules and the
qualified fallback hint. Version-19 dirty alpha and version-73 caller overlays
retain exact text/version through every switch. Repeated complete definitions
resolve to the marked dirty target or null. Frozen disk snapshots remain
unchanged, physical files retain their original bytes, and fresh servers over
the same settings and overlays reproduce each independently specified state.

Schema replacement changes value from i64 to string, removes gone and adds rank.
The valid states assert complete unknown-field diagnostics, labels and ordered
replacement candidates. Unsupported-version and missing artifacts assert exact
source warnings and metadata errors, with no old field hover or guessed source
definition. Disabling and restoring schema clears every previously published
owner. Repeated complete hover/null-definition results, original immutable facts,
overlay versions and fresh-server equivalence are checked for all six states.
Manifest roots/schema remain authoritative until a real watched deletion, when
the retained editor roots and metadata become active.

Rootless folder addition discovers existing closed definitions without synthetic
watch events. Add/remove/readd checks both cross-root bindings, full missing
import diagnostics and scratch ownership after removing the caller root. A
dirty definition survives removal and returns at its marked unsaved location
after readdition. Removing the package-owning folder drops the old graph and
host facts; readdition restores exact disk and schema facts. Fresh servers,
frozen snapshots, source versions and physical bytes remain independently pinned.
Malformed mixed folder batches are atomic. Empty/duplicate/absent and net-no-op
membership batches preserve generation, roots and repeated current navigation.

Real references workers are held before and after completion across both folder
and configuration changes. Only the complete ContentModified error can publish.
Matching integer/string cancellation takes priority and returns RequestCancelled;
an unmatched typed ID cannot cancel the other request. New definitions reflect
the current removed binding. A completed worker held across a net-no-op folder
batch returns the entire independently specified declaration/import/call list.
The existing five-second receive bound is retained.

Three client profiles pin semantic facts and the exact existing progress policy.
The shared initialization matrix additionally pins complete capabilities and
watcher registration policy. Configuration-capable and incapable clients receive
no server configuration pull. Absent, unsolicited, malformed-shaped and error
responses cannot change generation, roots, source bytes/version or static schema
facts; repeated navigation and hover retain the defaults. Incoming unsupported
workspace/configuration requests return complete MethodNotFound errors.
Malformed notifications and pre-initialize/post-shutdown configuration/folder
notifications remain silent and preserve current state.

Independent failures exposed invalid settings attempting to publish to an empty
URI and folder addition failing to discover existing sources. The retained
target/b09-2-repro.log precedes their fixes. Settings have no document identity:
the server now sends the standard
[window/logMessage](https://raw.githubusercontent.com/microsoft/language-server-protocol/gh-pages/_includes/messages/3.17/logMessage.md)
with ERROR type and the complete parse error while retaining valid configuration.
Explicit project configuration refreshes read sources through vela_package's
shared directory walker; package manifests remain authoritative. Directory
symlinks are not traversed, overlapping fallback roots deduplicate sources and
use the most specific root, and discovery does not run on every document edit.

A file used as a source directory independently exposes an I/O error on either
platform. target/b09-2-io-repro.log records the missing client-visible error before
its fix. The test gets only the platform OS message from std::fs; it independently
pins the real owner URI, complete project diagnostic, retained overlays, missing
binding, repair clear and current target. Source discovery failures have tracked
owners. Open/metadata diagnostics merge into one publication per URI, and repaired
owners receive empty clears. Closed metadata receives metadata facts only, so old
schema owners cannot inherit the active schema's source warning. The package test
also pins complete sorted/deduplicated source rows and atomic I/O failure owners.

Fixture authoring mistakes remain distinguishable from product failures: the
initial marker casing was invalid, schema facts require arrays, and valid schema
probes necessarily diagnose the independently absent field. Empty-root hints and
import references were initially omitted and have complete authored expectations.
The retained first/expanded/reviewed/owned-errors logs record those corrections;
expected outputs are never populated from provider results or reduced to counts.

Owned canonical temporary roots and explicit paths bound fixture writes/cleanup.
Fresh installed VSIX/native evidence must match this child's frozen source and
server on the registered Windows profile. macOS resumes shared progress with its
own fresh evidence. Accepted B00-B08 snapshots and prior children are preserved;
B16 remains deferred.
