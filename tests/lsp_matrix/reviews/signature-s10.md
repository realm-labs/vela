# Signature help: S10 ownership, clients and installed provider review

Scope: four `signature-help/syntax/S10/{positive,negative}/{service,protocol}`
obligations, `signature-help/environments/client_capabilities/protocol` and
`signature-help/editor/smoke`. New exact identities are
`signature::call_matrix_tests::signature_ownership_matrix_preserves_static_targets_and_lexical_shadowing`,
`tests::signature::call_matrix::signature_ownership_matrix_preserves_static_targets_and_lexical_shadowing`,
`tests::signature::call_matrix::signature_client_capability_matrix_preserves_triggers_labels_and_current_targets`
and installed test `signature help provider preserves exact Unicode signatures recovery and shadowing`.

`signature-s10` independently authors 17 complete templates and 75 positions:
35 positive and 40 null. Both layers execute LF/CRLF, repeat every full result
and preserve physical disk bytes. Service checks complete parameter names,
types/labels, defaults, active indexes, canonical symbols, named policy and all
eight applicable callable origins. Protocol uses real initialization/open and
request dispatch, explicit JSON null and independent UTF-16 positions in
isolated Chinese/space/percent paths. Expectations never come from providers.

The capability matrix runs all 75 positions at LF/CRLF under five profiles:
minimal, editor-like, explicit legacy flags, offsets without per-signature active
parameter support and the converse. Documentation formats, context support and
dynamic registration vary too. Each profile checks the exact advertised `(` and
`,` trigger characters and comma retrigger. Five request contexts cover omission,
invocation, opening bracket, comma retrigger and content change. Retriggers carry
an authored stale previous signature. All 3,750 positions plus repeats must keep
complete current simple-label signatures/root active indexes or explicit null;
offset support permits simple labels and does not require offset pairs. Cached
client help cannot supply target facts. No documentation or inner active-index
fields are invented.

`signature-editor` independently authors six templates and 21 baseline queries.
The installed VSIX driver checks exact provider results at initial, Unicode
multiline shifted, incomplete factory-call and close-to-disk states: 85 positions
per LF/CRLF variant, 170 total plus repeats. Source/imported functions, reordered
named/default parameters, inherent/default/direct-trait and returned members,
tuple variants, standard/builtin calls and local/parameter/capture/closure/type/
field/Any/unknown null boundaries all pass through the real language client.
Marker stripping independently supplies UTF-16 positions. The recovery state
also rechecks every baseline query. Source buffers and both physical files stay
unchanged by queries; dirty buffers close to original disk bytes and results.
The declaration file is never opened. No provider-registration retries are used.

These are static semantic, protocol and installed-provider proofs. Actual UX10
pointer/keyboard/rendered interactions and the remaining hover partitions are
separate open B07 work. Acceptance requires fresh current-source Windows or
macOS evidence from one registered profile; bundles cannot be combined.
