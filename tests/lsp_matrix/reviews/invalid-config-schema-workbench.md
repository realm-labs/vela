# Invalid configuration and schema workbench review

B09.5's two UX17 invalid configuration/schema obligations use an independently
authored twelve-state contract appended after the roots/settings proof. The
same saved multi-root workspace retains the right/left folder order, current
installed client, pinned profile settings and all four dirty source overlays.
Accepted edits use physical keyboard input, Explorer actions and pointer clicks;
the bridge only reads state and queries the installed hover provider.

The source fixture places Chinese/non-BMP text on preceding lines and pins field
UTF-16 ranges separately from native Go-to-Line positions. Actual Home/prefix
insertion creates unsaved authority without native indentation rewriting the
fixture body. Workspace/schema/TOML edits require full selection, Backspace,
an empty editor, exact inserted text and byte-for-byte physical Save. Native
schema and manifest deletion retain the exact visible platform confirmation;
Explorer recreation first proves a physically empty file and its active editor.

The states cover valid schema-one, rejected numeric roots, missing schema,
unsupported format99, schema-two, schema-one repair, actual schema deletion and
recreation, empty manifest, invalid TOML, valid package repair and manifest
deletion. Every state checks all three field hovers through separate provider
commands and physical keyboard chords: complete markdown/ranges, complete raw
Location-independent hover-or-null responses and the visible semantic or
unknown-field widget. Missing host metadata suppresses field hover widgets.

The numeric roots setting has an exact ERROR log, no changed source diagnostic
publication, and retained complete diagnostic/type facts. Schema failures have
`schema::diagnostic` metadata ownership and `schema::unavailable` source warnings,
including complete zero ranges, severity and empty labels/candidates/repair hints.
All five relevant open source owners are checked together. Previously seen
schema metadata owners must publish complete clears; no extra owner within the
fixture's root directories is accepted. Only the independently known physical
workspace prefix in schema error messages is replaced by `<workspace>`; the
complete relative filename, body, punctuation and byte offsets remain exact.

An empty manifest has no package/member declarations, so its valid graph grants
no left-folder source membership. Its dirty caller becomes scratch and both
imports are unresolved. The independent right anonymous root remains usable.
The manifest has no diagnostic owner until an error first occurs. Invalid TOML
must retain this established graph; byte spans are independently marked after a
Unicode comment, with literal LF/CRLF byte-coordinate goldens. Package repair
restores left alpha, but beta remains unresolved across the package boundary
without a dependency. Actual manifest deletion restores anonymous-root fallback,
both imports and configured schema facts, and clears the old manifest owner.

The backend `empty_then_invalid_native_manifest_keeps_scratch_until_package_repair_and_delete`
regression checks this entire graph chain in both line endings and all existing
client capability profiles, complete publication sets, repeated exact definitions,
unchanged overlay versions/text, immutable snapshots and unchanged disk fixtures.
These expectations come from marked fixtures and the package/source ownership
contract; neither provider output nor a native screenshot constructs an oracle.

The proof has a reviewed 120-second finite budget within the existing 450-second
aggregate workbench budget. A targeted Windows run passes all 423 actions,
238 checks and 36 command/native pairs. Closing B09.5 also requires all 48 native
proofs, the installed-extension regression and fresh strict prior-batch gate on
one frozen source/profile/server. Targeted success alone does not close the
child; macOS must collect its own fresh artifacts after switching machines.
