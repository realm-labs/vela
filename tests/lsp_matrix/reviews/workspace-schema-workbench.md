# Installed static schema replacement

B09.4 owns exactly the UX17 schema-replace Command and Input obligations.
Roots/settings, invalid configuration/schema and UX21 trust remain pending.
The independent `input-workspace-schema.json` authors a distinct `WorkbenchCell`,
a Unicode caller, its unchanged disk text and an unsaved prefix. Literal LF/CRLF
tests pin its UTF-16 spans. The native window already has a configured completion
artifact; fixture setup adds the distinct type/fields to that artifact before
launch, preserving the complete independently authored completion function facts.
It does not change the manifest or existing native action/expectation contracts.

Each of the original, replaced and restored states checks all three fields:
`value` changes from `i64` to `String`, `gone` disappears, and `rank` appears as
`bool`; restoring the original bytes restores all original facts. Each state
requires complete SDK hover contents/ranges and one complete native keyboard
hover request/response at each authored position. The exact unknown-field
diagnostic includes range, severity, source, labels, candidates and repair hints;
metadata diagnostic publications remain clear. After each replacement the
publication must come after its recorded mutation boundary. Original disk source,
full dirty buffer, language, caret and final artifact bytes remain checked.

Actual Quick Open pointer selection opens the configured artifact. External
keyboard selection, literal text insertion and Save replace it; no bridge write,
provider request or direct filesystem mutation performs these accepted actions.
The driver verifies the complete physical selection, clears it through Backspace,
checks the empty dirty editor and verifies the exact inserted source/caret before
Save. The first full run passes all 45 prior proofs but catches extra suffix
characters in the native JSON edit; this attempt is retained as a failed run.
These explicit selection/empty/source checks protect the input operation without
changing metadata, diagnostic or recovery expectations or retrying failed input.
The observer only reads complete SDK query results and editor state. The existing
bounded quiet-window observer waits for completed mutations without retrying
accepted input. Screenshots, ARIA, action receipts and complete client/server logs
are retained for each run. Schema loading does not execute host or script code.

The initial investigations retain an incompatible second `[host]` fixture setup
and a native diagnostic-hover expectation failure. A null language-provider hover
does not mean the editor hides its diagnostic tooltip: VS Code's marker hover
still shows the exact unknown-field message and source/code. The negative state
checks this complete diagnostic text, an empty schema label/content and a null
wire result, rather than demanding the unrelated diagnostic widget disappear.
The pinned workbench's `MarkerHoverParticipant` source supplies that UI contract.

A subsequent real Windows save exposes stale metadata despite a received file
event. The configured schema uses an uppercase drive; VS Code sends the lowercase
drive and an encoded colon. Before the fix, a separately authored Rust alias
reproducer fails against complete schema-state goldens. Both reload classification
and project schema matching now compare Windows drive/verbatim-prefix aliases,
without changing outgoing URI spelling or folding folder/file names. Schema
events keep the configured metadata document owner, avoiding duplicate owners for
the client alias. The alias regression covers LF/CRLF, complete changed/invalid/
missing/empty/restored results, one metadata publication and immutable snapshots.
The original non-alias regression remains intact. Shared path tests also pin
distinct files/drives and exact non-Windows case behavior.

Both registered platforms use their existing real keyboard bindings and the same
semantic contracts. Windows results cannot certify macOS. Each platform must
capture its own fresh VSIX/native evidence with unchanged source, fixture,
driver, binary and profile identities. B09.4 does not close B09 or defer any local
obligation to B16.
