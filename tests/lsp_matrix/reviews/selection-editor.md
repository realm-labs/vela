# Installed selection provider review

B10.38 closes only `selection/editor/smoke`. Two installed production VSIX
checks exercise the public `vscode.executeSelectionRangeProvider` command and
retain the complete paired `textDocument/selectionRange` requests/responses.
The extension development driver contributes no provider or language-client
middleware. Existing 25 editor checks and 50 native contracts remain intact.

The syntax manifest references 105 complete independently authored cases from
ten existing declaration, type, body, member, import, call, literal, pattern,
recovery and trivia fixtures. Every reference retains all ordered positions and
whole parent chains, including duplicates, points, an actual empty vector,
source/host/trait/dynamic/unknown ownership and malformed neighbors. Main dirty
overlays retain the original physical disk bytes, helpers undergo actual watched
changes, and closing main restores disk selection. Each public invocation and
wire vector repeats three times. All four Chinese/non-BMP LF/CRLF and shifted
forms use encoded private multi-root workspaces.

The separate lifecycle check retains all 43 phases, 46 actions and 11 authored
variants. Main/helper/renamed/decoy/missing views cover dirty changes, actual
save/close/reopen, hidden disk changes, deletion/recreation, physical rename and
simultaneous source/dependency damage/repair. Every phase checks every physical
file's exact bytes or absence. Public model queries temporarily open closed
owners, then close them before later watcher actions. An absent resource is
rejected by the SDK before LSP dispatch; three real command rejections must send
no owned selection request. Backend missing-document vectors remain covered by
the independent service/protocol lifecycle fixture.

Public expectations are authored from literal fixture bounds and the pinned
Microsoft SDK's selection rules. The SDK augments provider ranges with default
word/subword, whitespace-line, whole-model and trimmed/full-line ranges, sorts
and nests candidates, then converts them to public parent chains. Vela declares
no custom word pattern; all corpus lines fit the SDK's 1000-character window.
Raw wire expectations preserve exactly the authored Vela chain. Expected values
never come from live provider output. Independent Node geometry tests pin both
representations, UTF16/byte differences, literal bracket bounds, empty vectors,
duplicate order, lifecycle ownership and complete trace pairing.

The first prototypes exposed harness author errors: querying before activation,
launching a single-folder window that restarts the extension host on root addition,
omitting the existing literal fixture's explicitly authored `[` token rule, and
waiting for `didChange` after two consecutive identical empty-text edits.
The final harness uses bounded actual activation, the same multi-root workspace
shape as the formal runner, and the independently marked one-ASCII-byte bracket
extent already required by the Rust/Node literal contracts. Real edits with an
unchanged version must preserve identical source and EOL; they record the no-op
instead of inventing a mutation notification. Original failed
receipts/logs remain artifacts. No product policy or provider behavior changes.

The fresh formal run must complete both full four-form checks within their
